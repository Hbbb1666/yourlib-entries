YourLib

Minecraft Forge 1.20.1 的前置库模组。它不添加方块、物品、生物或玩法，只提供一套可编程的干预能力。

modid yourlib · 版本 0.1.0 · Forge 47.x · 无前置依赖 · 客户端为主，服务端做兼容

它解决什么问题

高机制 RPG 模组要做的事高度重叠：改这一击打出多少、拦截一次死亡、给实体打一个跨维度保留的标记、让某件物品不可摧毁、在世界里画一个法阵。这些活每个模组都要各自硬写一遍，而且互相踩踏——两个模组都想取消死亡事件时，结果取决于谁注册得更晚。

YourLib 把它们收敛成一组稳定的调用接口：下游只依赖它的 api 层，不必知道底层是 Forge 还是别的加载器，也不必再各自重写事件优先级与伤害管线。

设计原则

未激活时零影响

没有下游注册任何东西时，所有能力保持休眠，不改变游戏行为。监听器虽然常驻注册，但每条热路径开头先判断「是否被武装过」，没有就直接返回。

分级授权

稳定级能力默认可用；激进级会直接改写实体状态、可能破坏平衡或与其他模组硬冲突，必须由下游显式开启。

边界诚实

不承诺绝对免疫。能覆盖什么、覆盖不了什么，全部写在文档与页面上，包括下面那份清单。

能力模块 点开可跳到条目页对应分区

卡片的链接指向条目页里对应的分区，括号里是该模块的条目数量。

调用入口与分级

所有能力从单一门面取用。每条可引用条目都带运行时注解，标明家族、分级与前置条件，反编译也能读到。

事件与调度

自有事件总线：Lambda 注册、无反射开销、异常隔离、重复注册去重；免死走一条独立的裁决事件。

统一免死与穿透裁决

纯 Java 裁决器，不依赖 Minecraft。多个模组同时表态时，由固定规则给出唯一结果，而不是看谁注册得晚。

攻击库 33 条

逐武器穿透与减伤免疫、独立暴击、锚定伤害（定量伤害）、佩戴者穿透光环、真实伤害、分层击杀链、伤害债务。

防御库 17 条

免死、锁血、硬化、图腾封锁、来源免疫、击退免疫、暴击抗性、伤害反弹，以及把上述串成一次配置的链式入口。

Buff 库（状态与标记） 5 条

不占用原版效果通道的定时 Buff，可定义为不可清除；带分级的 UUID 标记，玩家标记跨维度保留，实体离开世界时自动清理。

物品保护与灵魂绑定

按标志位保护物品：防火、防仙人掌、防铁砧、防漂浮消失、掉入虚空返还、轮廓发光。绑定物品记住主人与快照，被丢弃或被指令清除后回到主人手中，数据写入世界存档。

移动与跳跃

限制传送与跨维度，覆盖末影人传送、/tp、紫颂果、末影珍珠、/spreadplayers；以及跳跃高度乘数。

渲染与视觉 7 条

服务端触发、客户端绘制的世界空间特效：光环、六芒星法阵、自上而下的光柱、地面环形法阵；另有自定义着色器、悬停面板、动态文字与 HUD 状态行。特效按客户端 tick 计时，不同帧率下寿命一致。

网络

一条自带通道，把特效从服务端下发到客户端。普通下游模组一般不需要直接接触。

配置驱动

六份可选配置文件：武器模板、客户端绘制分级与特效护栏、Buff 强制清除开关、Mixin 注入开关、兼容探针、死亡门控字段别名。整合包作者不写代码也能用。

安全、兼容与移植

击杀账本防止同一目标被重复结算；实体离开世界与玩家下线时清理记录，避免长跑服务器内存缓慢增长。api 与 core 两层不引用任何加载器包，构建期有脚本强制检查，同一份代码可编译在 ForgeGradle 与 Fabric Loom 下；换 Minecraft 版本等于换一个桥接模块。

应用前景

高机制 RPG 整合包

免死、锁血、图腾封锁、伤害债务、反弹、宿敌、定量伤害这一整套，正好对应 Boss 战、多阶段战斗、神器体系、软锁机制与剧情杀。以往要自己啃事件优先级与伤害管线，现在可以直接调用。

服务端 RPG 服务器

标记跨维度保留、实体离开世界自动清理、击杀账本防重复结算、异常隔离不影响其它模组。玩家数据与绑定物品写入世界存档，不依赖玩家在线状态。

内容创作者的「OP 级」工具

活动、剧情、调试，或需要让平衡性作废的特殊物品，可以一次性调用全部激进级手段；平时只用稳定级，不影响整合包平衡。

前置库生态

多个 RPG 模组共存时，最容易出问题的不是功能本身，而是两个模组都想取消死亡事件、都想改同一件武器的伤害。统一裁决与固定规则减少这类相互踩踏。

整合包作者无需写代码

武器模板与客户端护栏用配置文件完成，适合不想动 Java 的整合包作者。

跨加载器与跨版本

api 与 core 不依赖加载器，为后续向 NeoForge、Fabric 与更高版本迁移留出空间。Forge 1.21.1 已完成构建与启动验证，其余版本在推进中。

边界声明

免死与穿透依赖目标的伤害与死亡路径经过 Forge 的事件链。以下情况无法介入：

  • 目标用 Unsafe 直接写内存
  • CoreMod 级字节码替换
  • 用 Mixin 完全绕开 Forge 事件链的死亡
  • CoreMod 直接接管实体管理
  • 用 JNI 或本地库直接改写进程内存（Java 层的一切手段都看不到这一层）
  • Iris / Oculus 完全接管渲染管线

另外：完全无敌（isInvulnerableTo 恒为真）的目标不会触发伤害事件；绕过 setHealth 直接写血量数据的目标，落地加固拦不住。

没有被 YourLib 标记过的物品和实体，完全不受影响。

开发者接入

在 mods.toml 里声明依赖：

[[dependencies.myRpgMod]]
    modId = "yourlib"
    mandatory = true
    versionRange = "[0.1,1.0)"
    ordering = "AFTER"
    side = "BOTH"

然后在代码里通过门面调用：

YourLibApi api = YourLibApi.instance();

// 给玩家免死，并让手上的剑稳定级穿透护甲与附魔保护
api.combat().immortality(player.getUUID(), 0.5F, CancelPriority.BLOCKING);
api.combat().profile(ItemKey.of(sword))
        .penetration(WeaponPenetrationProfile.of(Set.of(
                DefenseType.PERCENTAGE_REDUCTION,
                DefenseType.ENCHANTMENT_PROTECTION), 1.0F))
        .universalReductionImmunity(1.0F);

完整条目清单见条目总览；随 jar 一起分发的还有 META-INF/yourlib-api-catalogue.md 与源码 jar，便于检索与二次开发。

当前状态

版本 0.1.0 的骨架与核心闭环已经可用，并在真实 Forge 1.20.1 客户端与服务端实测加载通过：模组注册、Mixin 注入、事件桥接、着色器注册均正常，无致命错误。

已知未完成项：

  • YourLibShaders 的多边形与星空着色器目前只有定义注册表，GLSL 载荷待补
  • 反监听与动态 Mixin 注入目前是预留开关，尚无运行时行为

以上两项不影响现有能力的正常使用。
